Antes de cualquier tarea de código, lee esta tabla. Si una fila coincide con la 
petición del usuario, abre SOLO el resource correspondiente. Si ninguna coincide, 
continúa sin abrir nada más de esta carpeta.

| Skill | Cuándo usar | Resource |
|---|---|---|
| buenas-practicas | **Siempre** que se vaya a escribir o refactorizar código, en cualquier área del proyecto. Es la referencia de calidad de código de xudoku. | resources/buenas-practicas.md |
| tdd-nueva-funcionalidad | El usuario pide crear una **funcionalidad nueva** que aún no existe (ej: "quiero que el jugador pueda pedir una pista", "añade un temporizador", "implementa selección de dificultad"). NO usar para bugfixes ni refactors. | resources/tdd-nueva-funcionalidad.md |
| tablero-core | Modificar/extender `SudokuBoard`; lógica de validación de constraints (fila, columna, caja 3×3); solver por backtracking (`solve`, `solveFrom`); contador de soluciones (`countSolutions`, `countFrom`); generador de tablero completo (`generateComplete`, `fillRandomised`); nuevo operador o método de acceso al tablero; depurar un puzzle que no se resuelve bien. | resources/tablero-core.md |
| generador | Modificar cómo se generan los puzzles (`SudokuGenerator.generateGame`); estrategia de eliminación de celdas (`removeCells`); por qué un puzzle tiene o no solución única; añadir semillas (`seed`) reproducibles; cambiar `MAX_RETRIES`; añadir/cambiar campos de `SudokuGame`; depurar puzzles con múltiples soluciones. | resources/generador.md |
| dificultad | Añadir/renombrar un nivel de dificultad; cambiar celdas visibles de un nivel existente; exponer dificultad en la UI (selector, label); entender por qué un nivel genera puzzles más/menos difíciles de lo esperado. | resources/dificultad.md |
| ui-tema | Cambiar colores; añadir/cambiar tipografía; activar/desactivar dynamic color (Material You); forzar modo oscuro/claro; crear UI de la pantalla principal; nuevos Composables o pantallas; configurar navegación; crear ViewModel de estado del juego. | resources/ui-tema.md |
| actualizar-documentacion | **Solo si el usuario lo pide explícitamente** (ej: "actualiza la documentación", "actualiza el index", "el skill de X está desactualizado", "acabo de cambiar Y, actualiza los docs"). NO activar automáticamente tras cada cambio de código — es un proceso manual y deliberado para no generar ruido en tokens. | resources/actualizar-documentacion.md |
